# 多机器人中控：项目背景与交接 v1.1

## 1. 目标与当前进度

为高校机器人团队构建统一中控，接入四驱车 `top_akm_dl`、无人机和宇树 Go2 X，完成事件上报、任务下发、受理回执、执行结果与断线后的会话恢复。

第一版在一台电脑上运行 4 个进程：中控、模拟机器狗、模拟无人机、模拟四驱车。机器狗上报“A 通道堵塞”，中控并行下发 OBSERVE 与 GUIDE，终端显示两项任务的 ACK 和 RESULT；随后注入丢包、重复、乱序与 5 s 链路中断，验证不会重复执行或补执行过期指令。

当前项目路径为 `D:\cppsoft\codex\ChatGPT\Robot`。本轮开始时目录为空，本轮仅新增项目文档，尚未编写通信、调度或模拟器代码，没有编译或运行结果。原交接中的 M0—M3 是计划，不是已完成状态；本地工具版本、远程仓库创建状态也未在本轮完整核验。

## 2. 分工与模块边界

| 角色 | 负责人 | 职责 |
|---|---|---|
| 中控通信 IO 层 | 丞翰 | 统一协议、传输、校验、队列、过期丢弃、去重、心跳、会话恢复、通信事实与指标 |
| 中控调度 LogicRouter | 子延 | 任务 ID、派单规则、任务状态、重试或放弃决策、业务结果展示 |
| 设备 agent | 各设备负责人 | 统一协议与原生 SDK/ROS/飞控接口的适配、任务受理、执行和结果、本地失控保护 |

通信层返回“已入队”不等于设备已受理，发送成功不等于执行成功。通信层上报已送达、未发送过期、送达未知、链路状态，并透传 ACK、RESULT、EVENT；调度层据此作出业务判断。设备自己上报任务终态，通信层不能伪造成功或失败。

事件源生成 trace_id；调度层给派生任务生成 task_id 并继承 trace_id。调度主动发起且无源事件时，trace_id 等于 task_id。接口与 mock 应尽早交给调度负责人，避免等待真实硬件适配完成后才联调。

## 3. 架构与通信方式

中控内部由调度层调用 IO 层，IO 与设备 agent 通信，agent 再调用各设备的原生接口。模拟器也必须经过真实消息路径，不通过进程内调用绕过 IO。真机接入时替换设备适配逻辑，尽量保持调度接口不变；这不代表原生协议适配可以省略。

| 设备 | 目前掌握的事实 | 接入取向与不确定性 |
|---|---|---|
| 四驱车 `top_akm_dl` | ROS 驱动使用 115200 串口；下发 11 字节、反馈 24 字节；当前导航输入偏航角速度 rad/s | 设备 agent 优先对接现有 ROS 驱动；实际固件与配置接机时核对 |
| 无人机 | 用户判断可能用 UDP，本地未找到无人机专用配置或协议资料 | 暂按 UDP 预留适配；MAVLink over UDP 为候选，不能认定已确认 |
| 宇树 Go2 X | 本地有通用 SportClient/API 头文件副本和一份整理笔记 | 通过官方 SDK/DDS；X 的固件权限、网口、服务和实际网络配置待确认 |

UDP 是传输层协议，MAVLink 是消息协议，两者可以同时使用。DDS 是中间件，也可能使用 UDP 承载；“UDP / DDS / 串口”只是工程接入方式的比较，并不处于同一协议层。

控制、遥测、载荷和管理按不同队列与通道组织：任务指令有投递截止和业务回执，遥测只保留最新帧，视频与点云使用独立载荷通道，日志与文件可以使用 HTTP/gRPC 等可靠传输。第一版只实现任务事件链路、心跳和恢复，不预先建设完整视频与文件系统。

原交接中的 1–20 Hz、≤100 ms 等属于控制场景参考值，不能直接用作所有高层任务的统一指标。高频 setpoint 由设备 agent 按原生接口要求发送；OBSERVE/GUIDE 是任务级消息。UDP 是本版模拟传输选择，不能推导出所有控制业务都必须禁止 TCP 或 HTTP；是否采用某种传输取决于截止、积压、故障和原生接口约束。

## 4. 本轮修正的关键语义

| 原草案问题 | 当前规定 |
|---|---|
| RESULT 既“只报一次”又要求重传 | 同一任务只产生一个终态；RESULT 可重传，中控以 RECEIPT 确认 |
| 业务受理与传输确认混用 | TASK/CANCEL 等业务 ACK；RECEIPT 只确认 EVENT/RESULT 收讫 |
| ACK 丢失后直接判未达 | 从未尝试发送才可记未发送过期；已发送无回执记送达未知，恢复时查询 |
| 跨设备使用单调时间截止 | 跨设备截止用 UTC Unix 毫秒并检查时钟偏差；本地等待和重试用 steady 时钟 |
| 执行总时长起点不明 | 设备首次受理 TASK 时开始计 execution_timeout_ms；中控的等待超时不等于设备停止 |
| CANCEL、查询、恢复未定义 | 增加 CANCEL、RECEIPT 与 LINK 查询/恢复字段 |
| trace_id、去重标识不完整 | 统一公共封装；msg_id 去重消息、task_id 去重任务、session_id 识别重启 |
| 单机“拔网线”验收 | 对指定设备双向屏蔽 UDP 5 s；物理网线不会切断本机回环 |
| mock 延迟后才 ACK | 先判断并返回 ACK，再模拟执行延迟，最后发送 RESULT |

设备掉线或回执超时不能证明任务未执行，不能直接换 task_id 重派。终态先于 ACK 到达时允许直接收尾；重复 RESULT 不重复触发业务。设备 agent 重启后若没有持久化记录，任务状态保持未知，不能承诺恢复后自动续跑。具体规则在接口协议中定义。

## 5. 设备资料与证据边界

原始资料根目录为 `D:\Application\WHEELTEC_R680_大车资料`，包括已解压的 ROS 功能包、协议手册 PDF、Go2 接口笔记与头文件、Noetic 源码压缩包和 R680 底盘资料。本轮只读相关源码、配置和文本，没有解压大型资料包或验证真机。

四驱车当前源码能直接证明帧结构、校验和上位机速度编码；底盘固件如何把速度和偏航角速度转换为舵角仍需固件或实机证据，不能用通用阿克曼模型代替核实。直接对接当前 ROS cmd_vel 接口时不需要自行把偏航角速度转换成转向角。

Go2 本地通用头文件能证明方法和 API ID，不能证明 X 的实机开放权限。价格、硬件配置、IP、DDS 版本、状态频率和仿真限制中，只有笔记转述而无本地原始证据的内容均保留为待确认。Damp 是阻尼控制相关接口，不把它写成已验证的最高优先级硬件急停。

转向角与偏航角速度是不同物理量，不能只做度转弧度后互换。若未来接口确实提供舵角，需要结合车速、轴距和底盘模型转换；当前四驱车 ROS 接口和 Go2 的预期高层速度接口都使用线速度与偏航角速度语义，但各自可用范围仍由设备定义。

## 7. 待补事实

1. 无人机型号、飞控/SDK、UDP 端口与实际消息协议，以及 OBSERVE 的区域定位和完成条件。
2. Go2 X 实机可用 SDK 方法、固件与运控服务管理权限、RJ45/Wi-Fi 条件、实际 IP 和 DDS 配置。

6. 演示是否需要录屏与报告，团队负责人对新增协议字段和能力范围的确认。

## 8. 后续实施顺序

先评审本轮接口文档并转成消息定义与 IO/mock 接口，再实现单机 UDP 四进程闭环和故障注入，随后逐项接入原生设备。统计优先输出任务耗时、回执等待与 RTT 分位数、遥测本地接收年龄，写清口径。原交接中的风险百分比、无出处吞吐下降数值和 79 ms 延迟预算不作为本项目的实测结果或验收依据。
