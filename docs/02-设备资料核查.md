# 设备接入

三种设备使用不同的原生接口，因此每种设备都需要 agent 把统一任务转换为设备操作。中控调度只处理“观察”“引导”等任务，不需要知道串口每个字节的含义或飞控 SDK 的具体函数。

开发建议先下载[协议与参考源码资料包](../materials/README.md)，结合本页确认接口，再实现对应 `sim/` 模拟器；模拟链路通过后，在 `agents/` 接入实机。下面的“当前依据”来自现有资料，不等于所有实机已经验证通过。

| 设备 | 当前依据 | 接入前确认 |
|---|---|---|
| 四驱车 top_akm_dl | ROS 源码：串口 115200，下发 11 字节、反馈 24 字节；当前导航输入为 m/s、rad/s | 实机固件、车型配置、导航目标与完成条件 |
| 无人机 | 暂按 UDP 设计，上层协议未确认 | 飞控型号、消息格式、端口、观察任务接口 |
| Go2 X | 通用 SDK 有 SportClient；X 实机权限未确认 | 可调用方法、固件、网络、运控服务 |

设备 agent 负责原生接口适配、任务受理、结果和本地失控保护。串口写入或 SDK 调用成功不代表任务完成。

## 三类设备如何实现任务

| 设备目录 | 需要实现 | 需要由设备负责人给出的定义 |
|---|---|---|
| agents/car/ | 收到 GUIDE 后导航到目标位置，及时返回受理或拒绝，执行结束后返回结果 | A_exit 等目标怎样映射到地图坐标；怎样认定到达；取消和断联后怎样停止 |
| agents/uav/ | 收到 OBSERVE 后完成区域观察，配合回执、结果和取消 | 区域 A 的位置、高度参考系、相机能力、观察完成条件与安全返回方式 |
| agents/dog/ | 将检测到的堵塞封装为 EVENT，保持心跳并处理消息确认 | 堵塞检测来自哪个程序；channel、block_ratio 如何取得；实机开放哪些接口 |

UDP 只说明报文怎样传输，不说明报文内容。无人机若采用 MAVLink over UDP，agent 仍需把 OBSERVE 转换为飞控能理解的操作；若采用厂商协议，则按厂商接口适配。Go2 的 DDS 是消息中间件，统一任务通过 SDK 适配，不把 DDS 发布成功当作任务成功。

## 四驱车串口参考

根据 `turn_on_wheeltec_robot/src/wheeltec_robot.cpp` 与 `include/wheeltec_robot.h`；实机接入前核对版本。成对数值均为大端有符号 16 位。

| 帧 | 字节布局（索引从 0 开始） |
|---|---|
| 下发 11 字节 | `0:7B`，`1–2:0`，`3–4:vx×1000`，`5–6:vy×1000`，`7–8:ωz×1000`，`9:XOR(0–8)`，`10:7D` |
| 反馈 24 字节 | `0:7B`，`1:Flag_Stop/预留`，`2–7:vx/vy/ωz`，`8–13:加速度xyz`，`14–19:角速度xyz`，`20–21:电压`，`22:XOR(0–21)`，`23:7D` |

反馈换算：速度 `/1000`（m/s、rad/s），加速度 `/1671.84`（m/s²），IMU 角速度 `×0.00026644`（rad/s），电压 `/1000`（V）。阿克曼车不支持横移，不能因帧中有 vy 就启用。

`top_akm_dl` 的 TEB 配置为 `cmd_angle_instead_rotvel: False`；angular.z 是偏航角速度，不是舵角。串口帧不含任务 ID、受理回执或导航完成结果，这些由 agent 提供。

实际开发优先复用现有 ROS 驱动和导航功能；只有需要改驱动或定位底层问题时才处理串口帧。启动时须选择 top_akm_dl 的车型配置，不能依赖其他车型的默认值。转向角与偏航角速度是不同物理量，不能仅做度与弧度换算后互换。

## Go2 X 接入边界

参考资料包含 SportClient 方法与 API ID，例如 Move、StopMove、Damp。通用 SDK 头文件说明接口存在，但不证明这台 Go2 X 的固件开放全部功能；高低层控制权限、运控服务、IP 与网口应在接机时确认。先完成状态或事件上报，再验证需要的控制方法；首版不开放跳跃、翻转等特技。

模拟器能验证统一协议的收发和状态处理，不能证明无人机飞行、车辆导航或机器狗动作已在实机可用。每个设备负责人需要分别记录模拟结果和实机验证结果。
